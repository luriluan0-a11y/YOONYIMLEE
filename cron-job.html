크론잡: 컴퓨터에게
시간표를 맡기는 법

크론잡(예약 실행)의 개념을 정리하고, Windows 작업 스케줄러로 예약 작업 2개를 직접 구성했습니다. 만드는 과정에서 찾아 고친 문제도 함께 기록했습니다.

크론잡Windows 작업 스케줄러PowerShellGit · GitHub Pages텔레그램 봇Claude Code

1. 크론잡이란?

정해진 시간마다 컴퓨터가 알아서 일을 하게 만드는 예약 알람입니다.

⏰알람 시계매일 아침 7시에 "띠리리링" 소리를 낸다
🤖크론잡매주 금요일 19:45에 그날 공부한 내용을 정리해서 올린다

이름의 뜻

크론(cron)은 그리스어 "크로노스(시간)"에서 온 이름이고, 잡(job)은 "할 일"입니다. 합치면 시간에 맞춰 하는 일입니다. 원래 리눅스·맥의 프로그램 이름이고, Windows에서는 작업 스케줄러가 같은 일을 합니다.

시간표 읽는 법: "분 시 일 월 요일"

크론 시간표는 칸 5개로 적습니다. *는 "아무 때나"라는 뜻입니다.

45분
19시
*일
*월
5요일 (금)

위 시간표 45 19 * * 5는 매주 금요일 19시 45분입니다. 요일은 0이 일요일, 5가 금요일입니다.

크론 시간표뜻
0 9 * * *매일 9시
0 9 * * 1-5평일(월~금) 9시
*/30 * * * *30분마다
0 0 1 * *매달 1일 0시
45 19 * * 5매주 금요일 19:45

2. 직접 만든 예약 작업 2개

개념만 보는 데서 끝내지 않고, 실제로 매일 쓰는 작업에 적용했습니다.

30분마다포트폴리오 자동 업로드

이 포트폴리오 사이트를 고치고 저장만 하면, 30분 안에 GitHub에 올라가 공개 페이지에 반영됩니다.

1
바뀐 파일이 있는지 확인없으면 아무것도 하지 않고 끝 (알림도 보내지 않음)
2
기록(커밋)하고 GitHub 내용 먼저 받아 오기GitHub에서 직접 고친 내용과 부딪히지 않도록
3
GitHub에 올리기 → 1~3분 뒤 공개 페이지 반영GitHub Pages가 자동으로 다시 만든다
4
성공 ✅ / 실패 ❌ 를 텔레그램으로 알림실패하면 어느 단계에서 왜 실패했는지와 해결 힌트를 함께 보낸다

매주 금 19:45금요일 학습 요약

그날 공부한 내용을 AI가 정리해 하루 기록과 이 포트폴리오의 "학습 기록"에 넣고 올립니다.

1
재료 모으기그날 바뀐 노트 목록 + 그날 AI와 나눈 대화
2
AI(Claude Code)가 지시서대로 정리하루 기록의 학습 표 채우기, 포트폴리오 학습 기록 항목 넣기
3
GitHub에 올리고 텔레그램으로 결과 알림위의 자동 업로드 스크립트를 그대로 다시 사용

AI가 지켜야 할 규칙도 지시서에 적어 두었습니다.

  • 재료에 없는 내용은 지어내지 않는다. 재료가 없으면 아무것도 고치지 않는다.
  • 내가 직접 쓴 하루 기록은 지우거나 바꾸지 않고, 빠진 항목만 더한다.
  • 공개 페이지에는 학습 내용만 쓴다. 개인 생활과 비밀 정보는 쓰지 않는다.
  • 공부만 한 것은 "정리", 직접 만든 것만 "제작"으로 써서 부풀리지 않는다.
  • 같은 날짜는 덮어써서 두 번 들어가지 않게 한다.

안전하게 만들기 위해 정한 것

걱정정한 방법
봇 토큰(비밀번호)이 새어 나갈 수 있다채팅이나 파일에 적지 않고, 직접 실행하는 설정 창에서 입력해 이 컴퓨터의 환경 변수에만 저장
30분마다 알림이 와서 귀찮다바뀐 것이 있을 때만 올리고 알림
컴퓨터가 꺼져 있어 금요일을 놓친다다음에 켜질 때 실행하고, 그 주 금요일 기준으로 정리
무엇이 언제 실패했는지 모른다모든 실행 결과를 기록 파일에 한 줄씩 남김

3. 만들면서 찾아 고친 문제

게임 QA를 준비하는 입장에서, "잘 돌아간다"고 믿지 않고 직접 실행해 확인했습니다.

확인한 방법발견한 문제 → 해결
설정 파일을 직접 실행문제창이 열리자마자 닫힘. 원인은 Windows의 스크립트 실행 제한 → 이번 실행에서만 제한을 푸는 실행 파일(.bat)을 만들어 해결. 컴퓨터 보안 설정은 바꾸지 않음
한글이 들어간 스크립트 점검문제Windows PowerShell 5.1이 한글을 깨뜨릴 수 있음 → 파일을 한글이 깨지지 않는 형식(UTF-8 BOM)으로 저장하고, AI에게 넘기는 명령은 영어로, 실제 지시는 파일에서 읽게 함
예약 시간을 기다리지 않고 시험 실행통과작업 스케줄러로 실제와 같은 방식으로 실행 → 하루 기록 4개 항목 추가, 포트폴리오 반영, 공개 페이지에서 바뀐 내용 확인 (약 30초)
시험 결과 파일을 직접 읽기문제실제 실행 시각은 18:48인데 기록에는 "19:45"로 적힘. 지시서에 시간을 고정해 둔 탓 → 날짜만 적도록 지시서 수정, 잘못된 기록도 바로잡음
변경이 없을 때 실행통과아무것도 올리지 않고 조용히 끝나는 것 확인

4. 돌아보기

무엇을 내가 하고, 무엇을 AI가 했는지 나눠 적었습니다.

내가 한 일
  • 무엇을 언제 자동으로 할지 정하기 (30분마다, 금요일 19:45)
  • 어느 저장소에 올릴지, 알림을 어디로 받을지 결정
  • 텔레그램 봇 만들기 (BotFather)
  • 예약 시간 전에 시험 실행 요청
AI(Claude Code)가 한 일
  • PowerShell 스크립트와 작업 스케줄러 등록
  • Git 저장소 연결과 업로드 명령
  • 문제 원인 분석과 수정
  • 시험 실행과 결과 확인

배운 점

· 자동화는 "언제(시간표) + 무엇을(할 일)"만 정하면 되지만, 실제로 쓰려면 실패했을 때 알 수 있는 방법(기록, 알림)이 꼭 필요하다.

· 예약 작업은 시간이 될 때까지 기다리지 말고 미리 한 번 돌려 보고 결과를 직접 읽어야 숨은 문제를 찾을 수 있다.

· 다음에 해 볼 것: 스크립트 한 부분을 직접 읽고 고쳐 보기, GitHub Actions로 같은 일을 서버에서 돌려 보기.

한 줄 정리
크론잡은 컴퓨터에게 시간표를 맡기는 것이다. 시간표를 정하는 것보다, 제대로 돌았는지 확인할 수 있게 만드는 것이 더 중요했다.

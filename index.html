작은 오류도 끝까지 확인하는
게임 QA, 이윤임입니다.

컴퓨터공학을 전공했고, AI 코딩 에이전트와 함께 만든 결과물을 직접 검수하며 문제를 찾아 고쳐 왔습니다. 눈에 보이는 결과만 믿지 않고 처음부터 다시 확인합니다.

소개

오류 32개가 가르쳐 준 것

어린 시절 아버지께서 컴퓨터 옆에 놓아두신 프로그래밍 책 한 권으로 코딩을 시작했습니다. 게임을 하면서 "이 화면 뒤에서는 어떤 코드가 돌아가고 있을까?"라는 궁금증이 커졌습니다.

혼자 공부하던 때 한 번에 오류 32개를 마주한 적이 있습니다. 30개는 하나씩 고쳤지만, 마지막 2개는 오류 메시지조차 원인을 알려 주지 않았습니다. 코드를 처음부터 한 줄씩 다시 읽었고, 대부분의 문제가 아주 작은 오타에서 시작된다는 것을 알게 되었습니다.

그 뒤로 눈에 보이는 결과만 믿지 않고 직접 확인하는 습관이 생겼습니다. 이 습관을 게임 QA에서 살리고 싶습니다.

강점 01

멈추지 않는 근성

"문제가 풀릴 때까지 멈추지 않는다"는 말을 자주 듣습니다. 모르는 것은 스터디에 직접 찾아가 질문합니다.

강점 02

놓치지 않는 꼼꼼함

띄어쓰기와 용어 하나까지 맞춥니다. 누가 읽어도 똑같이 이해하는 글이 좋은 버그 리포트라고 믿습니다.

강점 03

우선순위 가려내기

모든 것을 똑같이 붙잡지 않고, 중요한 것부터 처리합니다. 버그의 심각도를 나누는 QA 방식처럼요.

프로젝트

무엇을 만들었는지보다, 어떻게 확인했는지를 함께 적었습니다.

대표 게임 QA 채용 공고 보드

2026.10

게임잡과 알바몬에 흩어진 게임 QA 공고를 자동으로 모아, 필터와 마감일(D-day)을 보여 주는 웹 페이지를 만들고 GitHub Pages로 배포했습니다.

PythonHTML · CSS · JavaScriptGit · GitHub PagesClaude CodeVS Code

기능

  • 게임잡 QA 공고 10건, 알바몬 게임 QA·테스터 공고 11건 정리 (2026-10-16 기준)
  • "신입 지원 가능", "마감 7일 이내" 필터, 오늘 날짜 기준 D-day 계산
  • 제목에 QA·테스터가 없는 공고(게임 운영, 모니터링 등)는 자동으로 제외
  • 알바몬 접속이 실패해도 게임잡 결과는 만들어지도록 예외 처리
  • "취업준비"라고 입력하면 수집 → 정리 문서 → 웹 페이지까지 한 번에 만들어지는 자동화

QA 관점에서 찾아 고친 문제 6건

확인한 방법발견한 문제 → 해결
출력 결과를 직접 읽고 검수터미널에서 한글이 깨짐 → UTF-8 출력으로 수정
정리 문서의 표 확인공고 제목의 대괄호가 전각 문자 ［ ］로 바뀜 → 표기 방식 수정
수집 결과와 실제 사이트 화면 비교목록 주소로는 QA 필터가 적용되지 않음 → 실제 요청 주소와 QA 직무 코드를 찾아 해결
검색어별 결과 비교"QA 테스터"는 168건 중 대부분이 게임과 무관 → "게임QA", "게임테스터"로 변경
배포 후 링크 확인파일 이름을 바꾸자 예전 링크가 404 → 새 링크로 다시 공유
공고 링크 표본 확인게임잡·알바몬 링크 3개를 열어 정상 응답(200) 확인

실제 파일을 덮어쓰지 않도록 임시 폴더에서 먼저 실행해 결과를 확인한 뒤 반영했습니다.

내가 한 일 / AI가 한 일

내가 한 일필요한 기능 정하기, 결과 검수와 수정 요청, 검색어·파일 이름 규칙 결정, GitHub 계정 설정과 배포 결정
AI(Claude Code)가 한 일채용 사이트 구조 분석, 수집 스크립트와 웹 페이지 코드 작성, Git 명령 실행

학습 보관함 PARA 정리

2026.10

흩어진 학습 파일을 옵시디언에서 PARA 방법(진행 중인 일 · 계속 챙기는 일 · 참고 자료 · 끝난 일)으로 다시 구성했습니다. 이 사례를 지피터스 스터디에서 발표했습니다.

옵시디언마크다운PARA
  • 폴더 5개 구조 설계, 파일마다 "마감이 있나?" 같은 기준을 따져 직접 분류
  • 기준이 애매한 파일은 억지로 넣지 않고 따로 표시
  • 하루 기록 · 습관 트래커 · 지식 노트를 링크로 연결

AI 작업 규칙 문서화

2026.10

AI에게 일을 맡길 때마다 결과가 달라지는 문제를 겪고, 어떤 AI든 같은 규칙으로 일하도록 공통 규칙 파일(AGENTS.md)을 만들었습니다.

AGENTS.md프롬프트 작성문서화
  • 파일 이름에 날짜가 빠진 문제를 발견하고 원인(규칙이 문서에 없었음)을 찾음
  • 규칙을 "형식 + 예시 + 예외"로 구체적으로 정리
  • 이름이 바뀐 노트 3개와 연결된 링크까지 모두 수정

자동화 기초: 예약 실행부터 자동 배포·알림까지

  • 크론잡(예약 실행)의 개념과 "분 시 일 월 요일" 시간표 읽는 법을 정리하고, Claude와 함께 Windows 작업 스케줄러에 예약 작업 구성
  • 포트폴리오 사이트를 제작하고, GitHub 저장소와 연결해 30분마다 바뀐 파일만 자동으로 올리도록 구성 (PowerShell, Git, GitHub Pages)
  • GitHub Actions와 텔레그램 봇 알림 구조를 공부하고, 자동 업로드의 성공·실패를 텔레그램으로 알리도록 연결 (토큰은 파일에 남기지 않음)
  • 규칙 누락으로 생긴 노트 이름 오류를 찾아 고치고, 여러 AI가 같은 규칙으로 일하도록 공통 규칙 파일(AGENTS.md)로 정리
  • IDE(통합 개발 환경)의 구성 요소를 정리하고, 게임 QA 공고 수집 스크립트를 실행해 신규 공고 정리
